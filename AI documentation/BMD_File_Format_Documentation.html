1. Загальний огляд

BMD (Binary Model Data) — це бінарний формат файлів, що використовується 3D-двигуном Angelica2 (створений Archosaur Studio, 2004) для зберігання статичних попередньо-освітлених 3D-моделей. Ці моделі, як правило, використовуються для будівель, орнаментів та інших статичних об'єктів у грі.

Основні характеристики:

  • Пре-літинг — освітлення обчислюється заздалегідь і зберігається у файлах
  • Денна/нічна система — кожна вершина має денний та нічний колір, що інтерполюються за фактором часу доби
  • Колізія — BMD-файли можуть містити Convex Hull дані для системи фізики (CD = Collision Detection)
  • LightMap підтримка — у пізніх версіях додається підтримка світлових карт
  • Матеріали — початково відсутні, з'являються у версії 0x10000005+

Файлові розширення: .bmd (основний), іноді посилається як .lmd у картах (але на диску файли 'bmd')

Порядок байтів: Little-Endian (x86)

Джерело: Angelica3D SDK — A3DLitModel.h, A3DLitModel.cpp

2. Магічний заголовок файлу

Кожен BMD-файл починається з магічного заголовка, який ідентифікує формат:

// Магічний заголовок файлу struct BMD_FILE_HEADER { char[4] fileMagic; // "MOXB" (0x42584F4D) — бінарний BMD // АБО "MOXT" (0x54584F4D) — текстовий варіант uint32 modelVersion; // Версія моделі (див. нижче) };
ЗначенняHexОпис
"MOXB"0x42584F4DБінарний MOX — стандартний BMD файл
"MOXT"0x54584F4DТекстовий MOX (рідкісний)

Примітка: У випадку файлів Brush Building, перед магічним заголовком MOXB може бути додатковий префікс:

uint32  brushVersion  = 0x80000001  // ELBRUSHBUILDING_VERSION
bool    collideOnly                   // Тільки колізія (без рендерингу)

Парсер перевіряє: якщо перший DWORD == 0x80000001, це Brush Building файл, і він спочатку зчитує цей префікс, потім переходить до стандартного A3DLitModel.

3. Версії BMD та еволюція формату

Формат BMD еволюціонував через кілька версій. Є два рівні версій: версія моделі (A3DLitModel) та версія мешу (A3DLitMesh).

Версії A3DLitModel (рівень моделі)

ВерсіяHexОпис
Model v10x10000001Стара версія (меші використовують A3DLVERTEX з нормалями)
Model v20x10000002Поточна базова версія моделі
LightMap v10x10000100Модель з підтримкою LightMap (один файл світлової карти)
LightMap v20x10000101Модель з підтримкою LightMap (денна + нічна світлова карта)

Версії A3DLitMesh (рівень мешу)

0x10000001 — Mesh v1 (Застаріла)
Початкова версія. Використовує A3DLVERTEX (pos + diffuse + uv). Не підтримується — Load() повертає false.
0x10000002 — Mesh v2 (Стара)
Додає нормалі окремим блоком. Вершини: A3DLVERTEX (pos + diffuse + uv). Потім: indices, normals, AABB. Без денних/нічних кольорів.
0x10000003 — Mesh v3 (Денний/нічний колір)
Додає блоки dayColors[] та nightColors[] після normals. Формат вершин: A3DLVERTEX.
0x10000004 — Mesh v4 (Новий формат вершин)
Змінює формат вершин на A3DLMVERTEX_WITHOUTNORMAL (pos + diffuse + uv, без нормалей). Нормалі як і раніше окремим блоком.
0x10000005 — Mesh v5 (Матеріали)
Додає блок A3DMaterial після AABB. Містить ambient, diffuse, emissive, specular, power, twoSided.
0x10000006 — Mesh v6 (Поточна / Extra Colors)
Додає bool hasExtraColors після face_count. Якщо true — після nightColors додаються додаткові dayColorsExtra[] та nightColorsExtra[]. Поточна стандартна версія.
0x10000100 — Mesh LM (LightMap)
Підтримка LightMap. Після Material додає A3DLIGHTMAPCOORD[] (lm_u, lm_v для кожної вершини) та ім'я LightMap текстури (256 байт).

Трансформація моделі

Модель має 4 параметри трансформації, які визначають її позицію та орієнтацію у світі:

ПараметрТипОпис
scaleA3DVECTOR3 (12 bytes)Масштаб по осях X, Y, Z
directionA3DVECTOR3 (12 bytes)Напрямок “вперед” (зазвичай Z+)
upA3DVECTOR3 (12 bytes)Напрямок “вгору” (зазвичай Y+)
positionA3DVECTOR3 (12 bytes)Позиція центра моделі у світі

NormalizeTransforms: Двигун Angelica2 має операцію NormalizeTransforms(), яка “запікає” трансформацію у вершини. Після цього абсолютна матриця стає Identity, а всі вершини та нормалі вже знаходяться у світових координатах. Це дозволяє ефективніший рендеринг (немає потреби множити кожну вершину на матрицю).

5. Структура мешу (A3DLitMesh)

Кожен меш у BMD файлі має наступну загальну структуру:

// Загальна структура A3DLitMesh у файлі struct A3DLITMESH_FILE { uint32 version; // Версія мешу (0x10000002 – 0x10000100) char name[64]; // Назва мешу (null-terminated) char texture[256]; // Шлях до текстури (null-terminated) int32 vertCount; // Кількість вершин int32 faceCount; // Кількість трикутників // --- Для версії 0x10000006 (v6): bool hasExtraColors; // 1 байт — чи є додаткові кольори // --- Вершини (різний формат залежно від версії): VERTEX vertices[vertCount];// Вершини // --- Індекси: uint16 indices[faceCount * 3]; // Індекси трикутників (16-біт) // --- Нормалі: A3DVECTOR3 normals[vertCount]; // Нормалі (окремий блок!) // --- Кольори (якщо version >= 0x10000003): uint32 dayColors[vertCount]; // Денні кольори (ARGB) uint32 nightColors[vertCount]; // Нічні кольори (ARGB) // --- Додаткові кольори (якщо version == 0x10000006 && hasExtraColors): uint32 dayColorsExtra[vertCount]; uint32 nightColorsExtra[vertCount]; // --- AABB: A3DAABB aabb; // 48 байтів (Center + Extents + Mins + Maxs) // --- Матеріал (якщо version >= 0x10000005): A3DMaterial material; // --- LightMap координати (якщо version == 0x10000100): A3DLIGHTMAPCOORD lmCoords[vertCount]; };

6. Формати вершин за версіями

A3DLVERTEX (Mesh v2, v3)

Використовується у старіших версіях мешу. Містить нормаль вже у вершині.

struct A3DLVERTEX { A3DVECTOR3 pos; // 12 байтів — позиція (x, y, z) uint32 diffuse; // 4 байти — Diffuse колір (ARGB) float tu; // 4 байти — U координата текстури float tv; // 4 байти — V координата текстури }; // Разом: 24 байти на вершину // Потім у файлі окремо: нормалі (12 байт/вершина)

A3DLMVERTEX_WITHOUTNORMAL (Mesh v4, v5, v6)

Починаючи з версії 0x10000004, нормалі зберігаються окремим блоком, тому вершини стають легшими.

struct A3DLMVERTEX_WITHOUTNORMAL { A3DVECTOR3 pos; // 12 байтів — позиція (x, y, z) uint32 diffuse; // 4 байти — Diffuse колір (ARGB) float u; // 4 байти — U координата текстури float v; // 4 байти — V координата текстури }; // Разом: 24 байти на вершину // Потім окремо: // indices: faceCount * 3 * 2 = faceCount * 6 байтів // normals: vertCount * 12 байтів // dayColors: vertCount * 4 байтів // nightColors: vertCount * 4 байтів

A3DLMVERTEX (Повний, з нормалями та тангентами)

Використовується в рантаймі при LM_BUMP_ENABLE. Зазвичай не зберігається у файлі.

struct A3DLMVERTEX { A3DVECTOR3 pos; // 12 байтів A3DVECTOR3 normal; // 12 байтів uint32 diffuse; // 4 байти float u; // 4 байти float v; // 4 байти // При LM_BUMP_ENABLE додатково: // A3DVECTOR3 tangents; // 12 байтів // A3DVECTOR3 binormals; // 12 байтів };

7. Система денних/нічних кольорів

Одна з ключових особливостей BMD — це система денного/нічного освітлення. Кожна вершина має два кольори:

  • dayColor — колір вершини при денному освітленні
  • nightColor — колір вершини при нічному освітленні

Фактор DNFactor (від 0.0 до 1.0) визначає поточний час доби. Двигун інтерполює між денним та нічним кольором:

// Формула інтерполяції кольорів у A3DLitMesh::UpdateColors() n = DNFactor * 255; // Вага нічного кольору (0–255) d = 255 - n; // Вага денного кольору (0–255) // Для кожного каналу кольору (R та G обробляються разом): result = ((dayColor * d + nightColor * n) >> 8) & 0x00FF00FF; // Аналогічно для каналів G и B: result2 = ((dayColor2 * d + nightColor2 * n) >> 8) & 0x0000FF00; finalDiffuse = 0xFF000000 | result | result2;

Формат кольору — ARGB (uint32):

Byte layout: [A] [R] [G] [B] MSB → LSB Приклад: 0xFF808080 = повний альфа, сірий колір

Кольори присвоюються за замовчуванням при імпорті з MOX файлів або Blender:

ПараметрЗа замовчуваннямОпис
diffuse0xFFFFFFFFБілий (повна яскравість)
dayColor0xFF808080Сірий (помірна яскравість)
nightColor0xFF808080Сірий (помірна яскравість)

8. Матеріали

Матеріали з'являються у версіях мешу 0x10000005 та 0x10000006. Вони зберігаються після AABB.

// Структура матеріалу у файлі struct A3DMATERIAL_FILE { char name[...]; // C-string: "MATERIAL: " + назва A3DCOLORVALUE ambient; // 16 байтів (4 x float32) — Ambient колір A3DCOLORVALUE diffuse; // 16 байтів — Diffuse колір A3DCOLORVALUE emissive; // 16 байтів — Emissive колір A3DCOLORVALUE specular; // 16 байтів — Specular колір float power; // 4 байти — Specular power bool twoSided; // 1 байт — Двосторонній матеріал };

Двосторонній матеріал (twoSided): В Angelica2 двосторонній матеріал зазвичай означає листя дерев — коли тільки з одного боку рендеринг приховує задні грані, а twoSided робить їх видимими з обох сторін.

9. Одиничний об'ємний бокс (AABB)

Кожен меш зберігає свій AABB після кольорів. AABB складається з 4-х векторів по 12 байтів = 48 байтів.

struct A3DAABB { A3DVECTOR3 center; // 12 байтів — Центр боксу A3DVECTOR3 extents; // 12 байтів — Половина розміру по кожній осі A3DVECTOR3 mins; // 12 байтів — Мінімальні координати A3DVECTOR3 maxs; // 12 байтів — Максимальні координати }; // Зв'язок: // mins = center - extents // maxs = center + extents

Blender-експортер обчислює AABB автоматично з вершин мешу:

mins = (min(all_x), min(all_y), min(all_z))
maxs = (max(all_x), max(all_y), max(all_z))
center = (mins + maxs) * 0.5
extents = maxs - center

10. Лайтмапи (LightMap)

Починаючи з версії моделі 0x10000100, BMD підтримує LightMap — додаткову текстуру з попередньо обчисленим освітленням.

LightMap координати (у меші)

struct A3DLIGHTMAPCOORD { float u; // 4 байти — LightMap U координата float v; // 4 байти — LightMap V координата }; // 8 байтів на вершину

Імена LightMap текстур

Model VersionПольовіРозмір

11. Колізія (Hull / CD Brushes)

Система колізії BMD

BMD-файли мають розгалужену систему колізії, засновану на Convex Hull (опуклих оболонках). Це реалізується через класи CELBrushBuilding та CCDBrush.

Ключове розуміння: Колізійні дані — це НЕ частина A3DLitModel, а додаткові дані, що йдуть після A3DLitModel у Brush Building файлі. Звичайний BMD файл (тільки A3DLitModel) не містить колізійних даних. Колізія додається лише у Brush Building.

Структура Brush Building файлу

struct CELBRUSHBUILDING_FILE { uint32 version; // 0x80000001 (ELBRUSHBUILDING_VERSION) bool collideOnly; // Тільки колізія (без рендерингу) // --- A3DLitModel (standard BMD model): A3DLITMODEL_FILE litModel; // --- Кількість hull'ів: int32 numHull; // Кількість convex hull'ів // --- Hull Mesh List (зв'язок hull з мешами): for (i = 0; i < numHull; i++) { int32 numMesh; // Кількість мешів у цьому hull for (j = 0; j < numMesh; j++) { int32 meshId; // ID мешу в A3DLitModel } } // --- CD Brushes (дані колізії): for (i = 0; i < numHull; i++) { CCDBrush brush; // Дані опуклої оболонки } };

12. CELBrushBuilding — завантаження з колізією

Клас CELBrushBuilding — це основний клас для завантаження BMD файлів з колізією. Він містить:

class CELBrushBuilding : public CBrushProvider { A3DDevice* m_pA3DDevice; A3DLitModel* m_pA3DLitModel; // Модель для рендерингу int m_nNumHull; // Кількість hull'ів vector<MESHLIST> m_HullMeshList; // Зв'язок hull → меші vector<CCDBrush*> m_CDBrushes; // Convex hull для колізії DWORD m_dwTimeLived; // Час життя (для fade-in) bool m_bCollideOnly; // Тільки колізія };

CollideOnly прапорець

CollideOnly — це прапорець, який визначає, чи об'єкт використовується тільки для колізії без рендерингу:

  • collideOnly = true: Всім CD Brushes встановлюється прапорець CHDATA_SKIP_RAYTRACE, модель стає невидимою
  • collideOnly = false: Прапорці скидаються, модель стає видимою

Це дозволяє мати невидимі колізійні об'єкти у світі.

13. Hull Mesh List — зв'язок мешів з hull

Hull Mesh List — це структура даних, що визначає, які меші A3DLitModel належать кожному convex hull.

// Формат у файлі: for (hull = 0; hull < numHull; hull++) { int32 numMesh; // Кількість мешів у цьому hull for (mesh = 0; mesh < numMesh; mesh++) { int32 meshIndex; // Індекс мешу в A3DLitModel } } // Приклад: // numHull = 3 // hull 0: [0, 1] — меші 0 і 1 утворюють перший hull // hull 1: [2] — меш 2 — другий hull // hull 2: [3, 4, 5] — меші 3, 4, 5 — третій hull

Навіщо це потрібно? Convex hull обчислюється з вершин мешів. Hull Mesh List дозволяє групувати кілька мешів в один hull для колізії, або навпаки — розділяти різні частини моделі на окремі hull.

14. Ray Tracing по BMD

Система колізії BMD підтримує кілька режимів трасування:

TraceWithBrush() — основний метод

bool CELBrushBuilding::TraceWithBrush(BrushTraceInfo* pInfo, bool bCheckCHFlags) { // 1. Швидка перевірка по AABB моделі (+ 8.0f padding) A3DAABB aabb = GetModelAABB(); aabb.Extents += A3DVECTOR3(8.0f, 8.0f, 8.0f); // Для променя (ray): перевірка Ray-to-AABB if (pInfo->bIsPoint && !CLS_RayToAABB3(...)) return false; // Для об'єкта (sphere/AABB): перевірка AABB-AABB overlap if (!pInfo->bIsPoint && !CLS_AABBAABBOverlap(...)) return false; // 2. Тест по кожному CD Brush for (i = 0; i < numHull; i++) { // Перевірка прапорців (skip raytrace / skip collision) if (bCheckCHFlags) { DWORD flags = m_CDBrushes[i]->GetReservedDWORD(); if (pInfo->bIsPoint && (flags & CHDATA_SKIP_RAYTRACE)) continue; if (!pInfo->bIsPoint && (flags & CHDATA_SKIP_COLLISION)) continue; } // Trace по brush (opukla obolonka) if (m_CDBrushes[i]->Trace(pInfo) && pInfo->fFraction < fFraction) { // Оновити найближче влучання bCollide = true; } } return bCollide; }

Прапорці колізії (CHDATA flags)

ПрапорецьHexОпис
CHDATA_SKIP_RAYTRACE—Пропустити при променевій трасуванні (ray trace)
CHDATA_SKIP_COLLISION—Пропустити при зіткненні об'єктів (AABB overlap)

Чому два прапорця? Можна мати об'єкт, по якому можна ходити (collision = true), але промінь (наприклад, від камери) крізь нього проходить (raytrace = skip). Або навпаки — промінь від зброї зупиняється (raytrace), але гравець може пройти крізь (collision = skip).

Пріоритет результатів

При трасуванні по кількох brush'ах, вибирається найближче влучання (мінімальний fFraction):

if (pInfo->fFraction < fFraction) {
    fFraction = pInfo->fFraction;
    vNormal = pInfo->ClipPlane.GetNormal();
    bCollide = true;
}

16. Розбиття великих мешів (Word Indices)

Обмеження 16-бітних індексів: BMD формат використовує uint16 (WORD) для індексів вершин, що обмежує максимальну кількість вершин на меш до 65535.

Якщо меш має більше 65535 вершин, експортер автоматично розбиває його на кілька частин.

def _split_mesh_for_word_indices(mesh: BMDMesh) -> List[BMDMesh]:
    if len(mesh.vertices) <= 65535:
        return [mesh]

    chunks = []
    local_vertices = []
    local_indices = []
    remap = {}
    part = 1

    for tri in chunks_of(3):
        # Додаємо нові вершини, які ще не в поточному шматку
        needed = [idx for idx in tri if idx not in remap]
        if len(local_vertices) + len(needed) > 65535:
            flush()  # Зберігаємо поточний шматок

        # Додаємо вершини з ремапом індексів
        for idx in tri:
            if idx not in remap:
                remap[idx] = len(local_vertices)
                local_vertices.append(mesh.vertices[idx])
            local_indices.append(remap[idx])

Результат: меші перейменовуються з додаванням суфікса (Plane13_01, Plane13_02, ...).

17. Система трансформацій

Angelica2 використовує row-major матриці 4x4 для трансформацій. Абсолютна матриця моделі обчислюється як:

absoluteTM = Inverse(normalizedTM) * Scale(scale) * TransformMatrix(dir, up, pos)

де:

КомпонентОпис
Scale(scale)Діагональна матриця масштабу
TransformMatrix(dir, up, pos)Матриця орієнтації та позиції
Inverse(normalizedTM)Обернена матриця “нормалізованої” трансформації

Трансформація вершин:

worldPos = vertex.pos * absoluteTM;
worldNormal = normalize(normal * absoluteTM_rotation_only);

18. Конвертація осей

Blender використовує систему координат Z-up, а Angelica2 — Y-up. Конвертація:

РежимПеретворенняОпис
BLENDER_TO_A3D(x, y, z) → (x, z, y)Замінюємо Y ↔ Z
NONE(x, y, z) → (x, y, z)Без змін

Порядок вузлів у вершинному форматі A3DLMVERTEX у файлі завжди (x, y, z) — Y-up. Blender-експортер здійснює конвертацію перед записом.

20. Практичні поради

Створення BMD з нуля

  • Використовуйте Blender 4.5+ з bmd_blender_exporter.py
  • Для сумісності з існуючими файлами використовуйте референсний файл litmodel_1222.bmd
  • Версія v4 (REFERENCE_V4) — найбезпечніший вибір без матеріалів

Аналіз існуючих BMD файлів

  • Запустіть експортер як скрипт: python bmd_blender_exporter.py path/to/file.bmd
  • Це виведе JSON-резюме структури файлу
  • Для перегляду бінарного вмісту використовуйте xxd або十六进制 редактор

Типові помилки

  • Невідповідність winding order: Якщо модель виглядає “вивернутою”, спробуйте flip_winding
  • Текстури не завантажуються: Перевірте, що шлях текстури відносний до кореня гри
  • Більше 65535 вершин: Меш автоматично розбивається, але це може вплинути на UV та нормалі на швах
  • Колізія не працює: Звичайний BMD не має колізії! Потрібен Brush Building файл
