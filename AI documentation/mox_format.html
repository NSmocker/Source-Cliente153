1. Огляд формату

.mox — це формат файлу 3D-моделей движка Angelica 2 (Archosaur Studio), що використовується в грі Perfect World. Файл містить ієрархічну структуру Frame → Mesh, де кожен фрейм може містити меші та дочірні фрейми.

Формат підтримує два режими серіалізації:

  • Бінарний (AFILE_BINARY) — основний формат для ігор
  • Текстовий (AFILE_TEXT) — для редакторів та відладки
Ключовий факт: Файл з розширенням .mox — це файл класу A3DFrame. Він завантажується через A3DFrame::Load(). Файли .mod (A3DModel) посилаються на .mox файли як дочірні фрейми.
Для трави: Файл .mox для трави повинен містити рівно 1 меш та 0 дочірніх фреймів (перевірка в EL_GrassType.cpp:83).

3. Загальна структура .mox файлу

Файл .mox має рекурсивну структуру. Кожен фрейм може містити меші та дочірні фрейми:

.mox файл (A3DFrame) ├── VERSION — версія формату (1 або 2) ├── FRAME: <name> — назва фрейму ├── FRAMECOUNT: N — кількість кадрів анімації │ └── Relative Transform Matrices — A3DMATRIX4 × N ├── BOUNDINGBOXNUM: N — кількість OBB │ └── OBB Data — формат залежить від версії (V1/V2) ├── MESHCOUNT: N — кількість мешів │ └── A3DMesh[] — кожен меш містить вершини, індекси, текстуру, матеріал └── CHILDCOUNT: N — кількість дочірніх фреймів └── A3DFrame[] — рекурсивна структура

6. Формат вершин (A3DVERTEX)

Основний формат вершин для мешів у .mox:

ПолеТипОпис
x, y, zfloat × 3Позиція вершини
nx, ny, nzfloat × 3Нормаль вершини
tu, tvfloat × 2Текстурні координати

FVF (Flexible Vertex Format): D3DFVF_XYZ | D3DFVF_NORMAL | D3DFVF_TEX1

Розмір однієї вершини: 32 байти (8 float × 4 байти)

Формат для трави (GRASSVERTEX)

ПолеТипОпис
posA3DVECTOR3 (float × 3)Позиція
normalA3DVECTOR3 (float × 3)Закодовано: normal.x = normal.z = 0, normal.y = вага вітру (від 0 до 1 залежно від висоти)
u, vfloat × 2Текстурні координати
Для трави: Поле normal.y використовується для кодування ваги вітру — чим вища вершина, тим більше вона рухається від вітру. Значення обчислюється як (y / vHeight)^2.

10. LOD система

Меші можуть містити дані для Level of Detail (LOD):

// LOD дані (якщо bHasLOD == true)
float  vLODMinDist    // дистанція, з якої починається LOD
float  vLODMaxDist    // дистанція, на якій LOD максимальний
int    iLODLimit      // мінімальна кількість вершин (не менше 3)
WORD[] MapTable       // таблиця мапінгу: MapTable[i] = індекс вершини для злиття

Алгоритм LOD:

  1. Обчислюється відстань від камери до центру мешу, з урахуванням FOV
  2. Якщо vDis < vLODMinDist → повна деталізація (100%)
  3. Якщо vDis > vLODMaxDist → мінімальна деталізація (0%)
  4. Між цими значеннями — лінійна інтерполяція
  5. Вершини злиття замінюються через MapTable, поки не досягнуто iLODLimit

11. Lightmap підтримка

При MESHVERSION_SUPPORT_LIGHTMAP = 100 після стандартних даних мешу додаються:

// Lightmap UV-координати для кожного кадру
A3DLIGHTMAPCOORD[nFrameCount][nVertCount]

struct A3DLIGHTMAPCOORD {
    float u;    // U-координата lightmap
    float v;    // V-координата lightmap
};

Це дозволяє використовувати додаткову текстуру освітлення (lightmap) для кожної вершини мешу.

12. Система трави — використання .mox

Система трави використовує .mox файли як шаблони для генерації трави на терені.

Завантаження .mox для трави

// EL_GrassType.cpp::Init()
A3DFrame * pGrassFrame = new A3DFrame();
AFileImage moxFile;
moxFile.Open(szGrassFile, AFILE_OPENEXIST | AFILE_BINARY);
pGrassFrame->Load(m_pA3DDevice, &moxFile);

// Перевірка: трава = рівно 1 меш, 0 дочірніх фреймів
if (pGrassFrame->GetNumChilds() != 0 || pGrassFrame->GetNumMeshes() != 1)
    return false;

// Витягуємо дані мешу як шаблон
A3DMesh * pGrassMesh = pGrassFrame->GetFirstMesh();
m_nNumOneGrassVert = pGrassMesh->GetVertCount();
m_nNumOneGrassFace = pGrassMesh->GetIndexCount() / 3;

Конвертація вершин трави

// Вершини з .mox конвертуються в GRASSVERTEX
// normal.y використовується як вага вітру
float vHeight = aabb.Maxs.y - aabb.Mins.y;

for (i = 0; i < m_nNumOneGrassVert; i++) {
    vert.pos.x = pMeshVerts[i].x;
    vert.pos.y = pMeshVerts[i].y;
    vert.pos.z = pMeshVerts[i].z;

    // Закодована вага вітру в normal.y
    vert.normal.x = vert.normal.z = 0.0f;
    vert.normal.y = pMeshVerts[i].y / vHeight;
    vert.normal.y *= vert.normal.y;  // квадратична залежність

    vert.u = pMeshVerts[i].tu;
    vert.v = pMeshVerts[i].tv;
}

Рендер трави

  • Трава рендериться шляхом багаторазового копіювання шаблонного мешу з різними трансформаціями
  • Використовується кастомний pixel shader (grassrender.txt) та vertex shader для анімації вітру
  • Терен ділиться на блоки розміром 16×16 (GRASS_BLOCKSIZE), кожен блок містить бітову карту розміщення трави
  • Підтримується LOD на рівні блоків та день/ніч освітлення через lightmap
  • Є підтримка рефракції (рендер під водою)

Структура файлів трави

grasses/ ├── badgrass.mox — fallback меш при відсутності файлу ├── grass01.mox — шаблон трави (1 меш, 0 child frames) ├── grass02.mox ├── ... └── Textures/ └── grass01.dds — текстура трави (звичайно альфа-тестована)

13. Формат .mod (A3DModel)

Файл .mod — це модель, яка посилається на .mox файли як дочірні фрейми:

// A3DModel::Load (.mod файл)
VERSION: 2
MODEL: MyModel
{
    CHILDFRAME: 2           // кількість посилань на .mox файли
    {
        body.mox            // ім'я .mox файлу
        weapon.mox
    }
    CHILDMODEL: 0           // кількість дочірніх моделей
    {
    }
    ACTIONS: 3              // анімаційні дії
    {
        idle
        0, 30, 1            // start, end, loop
        walk
        31, 60, 1
        attack
        61, 90, 0
    }
    GROUPACTIONS: 1
    {
        combat
        idle
        attack
        ...
    }
}
GFXEVENT: 0                // події графічних ефектів
SFXEVENT: 0                // події звукових ефектів
LOGICEVENT: 0              // логічні події
USER_PROPERTY DO NOT EDIT  // користувацькі властивості (32 байти)
