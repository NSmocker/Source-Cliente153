1. Overview & Architecture

The .gfx file format is the visual effects file format used by the Angelica Engine (Angelica2 / Angelica3). It stores particle effects, decals, trails, lightning, sounds, 3D models, and composite sub-effects in a single file. GFX files can be in text (human-readable) or binary format.

High-Level Architecture

A3DGFXExMan (Manager) | +-- LoadGfx() creates A3DGFXEx objects |-- Manages render containers (2D back/front, 3D default/custom) |-- Particle pool, texture manager, stream manager, model manager |-- Thread-safe loading with callbacks | +-- A3DGFXEx (Single GFX Effect) |-- File version (150), default scale/speed/alpha |-- Camera shake, AABB, fade-by-distance settings |-- Vector of A3DGFXElement* (m_EleLst) |-- Element name map (m_EleMap) |-- PhysDataMan for .gphy companion | +-- A3DGFXElement* (Base Element) |-- Name, shader, texture, pixel shader |-- Bind/dummy element references |-- KeyPointSet (animation keyframes) |-- Tile mode, UV manipulation, render layer |-- Subclasses: Decal, Trail, Particle, Lightning, Ring, Model, Sound, Container, GridDecal, PhysElement, ECMModel, Ribbon, Paraboloid

File Extensions

ExtensionDescription
.gfxMain visual effects file
.gfx3Angelica 3 variant (higher version number)
.gphyCompanion physics data file (same name as .gfx)
Key Fact: A single .gfx file can contain many elements of different types. Each element is independently animated via the KeyPoint system. The file format supports both text and binary encoding, detected at runtime via AFile::IsBinary().

2. File Structure (Text Mode)

In text mode, the file is a series of key: value lines. Lines are read sequentially. Each line follows the format Key: Value where the key is a literal string.

3. Binary Format

The binary format is a packed version of the text format. Fields are written in the exact same order as the text format, but as raw bytes.

Binary File Header

DWORD   m_dwVersion;            // 4 bytes, little-endian
float   m_fDefScale;            // 4 bytes
float   m_fDefPlaySpeed;        // 4 bytes
float   m_fDefAlpha;            // 4 bytes
bool    m_bUseRaytrace;         // 1 byte
bool    m_bFaceToViewer;        // 1 byte
bool    m_bFadeByDist;          // 1 byte
float   m_fFadeStart;           // 4 bytes
float   m_fFadeEnd;             // 4 bytes
float   m_AABBOrg.Mins[3];      // 12 bytes (3 floats)
float   m_AABBOrg.Maxs[3];      // 12 bytes (3 floats)
// If ShakeCam != NONE:
  <ShakeNoise data (variable)>
DWORD   m_ElementCount;         // 4 bytes

Binary Element Header

int     m_nEleType;             // 4 bytes (element type ID)
String  m_strName;              // length-prefixed string
int     m_Shader.SrcBlend;      // 4 bytes
int     m_Shader.DestBlend;     // 4 bytes
int     nRepeatCount;           // 4 bytes
DWORD   nRepeatDelay;           // 4 bytes
String  m_strTexture;           // length-prefixed string
String  m_strBind;              // length-prefixed string
bool    m_bZEnable;             // 1 byte
int     m_nTexRow;              // 4 bytes
int     m_nTexCol;              // 4 bytes
DWORD   m_dwTexInterval;        // 4 bytes
int     m_nPriority;            // 4 bytes
bool    m_bDummy;               // 1 byte
String  m_strDummy;             // length-prefixed string
bool    m_bWarp;                // 1 byte
bool    m_bTileMode;            // 1 byte
float   m_fUOffsetSpeed;        // 4 bytes
float   m_fVOffsetSpeed;        // 4 bytes
int     m_nRenderLayer;         // 4 bytes

After the base element header, the element-specific Load() method reads its own data, then the KeyPointSet is loaded.

Binary strings are length-prefixed: a DWORD (4 bytes) length, followed by that many characters (not null-terminated in some implementations).

6. KeyPoint Animation System

The KeyPoint system is the core animation mechanism. Each element contains a KeyPointSet which holds a list of KeyPoint objects. Each KeyPoint defines a transform state (position, rotation, color, scale) and a time span. Between KeyPoints, the engine interpolates to create smooth animation.

6.1 KEY_POINT Structure

struct KEY_POINT {
    A3DVECTOR3      m_vPos;     // Position (x, y, z)
    A3DCOLOR        m_color;    // RGBA color (4 bytes, ABGR format in memory)
    float           m_fScale;   // Uniform scale factor
    A3DQUATERNION   m_vDir;     // 3D rotation quaternion (x, y, z, w)
    float           m_fRad2D;   // 2D rotation angle (radians, around Z axis)
};

6.2 KeyPointSet

The A3DGFXKeyPointSet manages a sequence of KeyPoints with timing and looping:

class A3DGFXKeyPointSet {
    vector<A3DGFXKeyPoint*> m_KeyPointArray;  // Array of key points
    DWORD   m_dwTimeStart;      // Start time offset (ms)
    DWORD   m_dwTimeSpan;       // Current elapsed time (ms)
    int     m_nRepeatCount;     // Loop count (-1 = infinite, 0+ = finite)
    int     m_nCurRepeat;       // Current loop iteration
    DWORD   m_dwRepeatDelay;    // Delay between repeats (ms)
    DWORD   m_dwCurDelay;       // Current delay countdown
    int     m_nActKeyPoint;     // Currently active key point index
    bool    m_bInDelay;         // Currently in repeat delay
    PROC_DATA m_ProcData;       // Processed/interpolated data
};

8. Texture Animation System

Each element supports two texture animation modes:

Sprite Sheet Mode (TileMode = 0)

Texture is divided into a grid of TexRow x TexCol frames. Frames advance at TexInterval ms each.

TexRow: 4           // 4 rows in sprite sheet
TexCol: 4           // 4 columns in sprite sheet
TexInterval: 100    // 100ms per frame
TexAnimMaxTime: 0   // 0 = loop forever

UV Scrolling Mode (TileMode = 1)

Texture UV coordinates scroll continuously at given speeds.

TileMode: 1
TexSpeed: 0.500000  // U scroll speed
TexSpeed: 0.000000  // V scroll speed

9. Pixel Shader Constants

Starting from version 91, elements can have pixel shader constants that animate over time.

PSFileVersion: 1
ShaderFile: my_effect.psh       // Pixel shader file path
ShaderTex: noise.dds            // Additional texture for shader
PSConstCount: 2                 // Number of constant registers

// For each constant:
PSConstIndex: 0                 // Register index
PSConstValue: 1.0, 0.5, 0.0, 1.0  // Initial value (r, g, b, a)
PSLoopCount: -1                 // Loop count (-1=infinite)
PSTargetCount: 3                // Number of target values

// For each target:
PSInterval: 500                 // Time to reach this target (ms)
PSConstValue: 0.0, 1.0, 0.5, 1.0  // Target value
Pixel Shader Target Animation: If interval > 0, the value interpolates from previous value to target over that time. If interval = 0, it's an instant jump. If interval < 0, it acts as a "hold" marker (value stays at previous level for |interval| ms).

11. Physics Data (.gphy)

Physics-enabled elements store their data in a separate .gphy file with the same base name as the .gfx file. The GFX file header contains PhysExist: 1 when physics data is present.

// Example: explosion.gfx has PhysExist: 1
// Engine looks for: explosion.gphy in the same directory
// Contains PhysX scene data for particle physics

14. Notes for Unity Integration

Key Implementation Points for a Unity Plugin:
  • Parse text format first — it's human-readable and easier to debug. Binary format follows the exact same field order.
  • Version checking — always check Version: N before reading version-gated fields. Missing fields = default values.
  • Element type dispatch — use the GFXELEMENTID to determine which subclass properties to parse after the base element data.
  • KeyPoint interpolation — implement enumInterpAll (SLERP for quaternions, LERP for position/color/scale) as the primary mode.
  • Control methods — each KeyPoint can have multiple modifiers. Process them in order during tick.
  • Bind system — elements can follow other elements' transforms via the BindEle name reference.
  • RepeatCount = -1 means infinite loop; positive values loop that many times.
  • AABB — stored as min/max vectors, used for frustum culling. Scale by the effect's scale factor.
  • Texture paths — relative to Gfx/Textures/ directory.
  • Container elements — reference other .gfx files recursively.
  • Color format — RGBA stored as 4 separate ints in text, or as a 32-bit ABGR value in binary.
  • Quaternion format — x, y, z, w order in text files.
  • Time units — all time values are in milliseconds.
Gotchas:
  • The DedaultScale field has a typo (should be "Default") — keep the typo for compatibility.
  • Binary strings are length-prefixed DWORD + chars (no null terminator in some cases).
  • AABB is stored as Mins/Maxs (center+extent is computed at load time).
  • Shake camera noise is a full A3DGFXCtrlNoiseBase serialized inline.
  • Elements with BindEle are saved AFTER unbound elements in the file.
  • PhysX elements need a separate .gphy file — without it, those elements won't work.
