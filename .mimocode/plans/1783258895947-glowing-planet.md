## Key Format Findings

### .mox File = A3DFrame File
The `.mox` extension is used by `A3DFrame` (the mesh/frame container). A `.mod` file (A3DModel) references child frames as `.mox` files.

### Frame Version Constants
- `FRAMEVERSION = 2` (current)
- Version 1 (old) used different OBB bounding box format

### Mesh Version Constants
- `MESHVERSION = 2` (standard mesh)
- `MESHVERSION_SUPPORT_LIGHTMAP = 100` (mesh with lightmap support)

### Two serialization formats: Binary and Text

### Frame (.mox) binary structure:
1. `VERSION: <int>` (string)
2. `FRAME: <name>` (string)
3. `nFrameCount` (int)
4. Relative transform matrices (A3DMATRIX4 * nFrameCount)
5. Bounding boxes (V1 or V2 depending on version)
6. Mesh count + meshes
7. Child frame count + child frames

### Mesh binary structure:
1. `VERSION: <int>`
2. `MESH: <name>`
3. vertCount, indexCount, frameCount (ints)
4. hasLOD, isWire (bools)
5. Mesh properties (V1 or V2)
6. Indices (WORD array)
7. LOD data (if hasLOD): minDis, maxDis, limit, mapTable
8. Frame vertices (A3DVERTEX per frame)
9. Optional detail texture + matrix
10. Texture name
11. Material
12. Optional lightmap coords (if version == 100)

### A3DVERTEX format (FVF = XYZ | NORMAL | TEX1):
- x, y, z (float) — position
- nx, ny, nz (float) — normal
- tu, tv (float) — texture coordinates

### Grass rendering specifics:
- Grass .mox files must contain exactly 1 mesh, 0 child frames
- Loaded via `A3DFrame::Load()` from binary .mox
- Vertex normal.y encodes wind weight (height-based)
- Rendered with custom pixel shader (`grassrender.txt`)
- Uses `GRASSVERTEX` format: pos + normal(wind index + weight) + uv
